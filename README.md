# Gladiator HTML

Быстрый web-прототип игры про гладиаторскую школу. Игрок распределяет трёх гладиаторов — каждый используется ровно один раз — по трём видимым противникам, смотрит все три боя серии и видит итог школы.

Правило контр-треугольника всегда на экране: `heavy → fast → technical → heavy`, где стрелка означает «имеет архетипное преимущество против». Серия всегда играется до конца; `Rematch` возвращает в планирование с тем же сидом, чтобы можно было проверить другой состав на том же вызове.

URL-параметр `?seed=<uint32>` воспроизводит ту же серию: случайность полностью детерминирована для одинаковых назначений, сида и числа тиков.

## Запуск

Нужны Node.js 22+ (или 20.19+) и npm.

```bash
npm install
npm run dev
```

Vite откроет приложение на `http://127.0.0.1:4173` и будет обновлять его без полной перезагрузки.

## Проверки

```bash
npm test                 # быстрые unit-тесты simulation
npm run test:watch       # unit-тесты в watch-режиме
npm run test:e2e         # Playwright smoke + planning screenshot baseline
npm run test:e2e:update  # принять намеренное изменение planning screenshot
npm run build            # TypeScript + production build
npm run check            # всё перед передачей работы
```

Перед первым e2e-запуском может понадобиться `npx playwright install chromium`.

## Структура

- `src/simulation/` — чистые правила и состояние серии и боя; `series.ts`, `fighters.ts` и `random.ts` остаются независимыми от рендера и не импортируют DOM или Three.js.
- `src/presentation/` — Three.js-сцена, которая только отображает состояние симуляции.
- `src/main.ts` — короткий runtime-loop и привязка HTML UI.
- `tests/` — Playwright smoke и эталонный screenshot planning-экрана.

Пауза и скорость `×1/×2/×4` влияют только на runtime (сколько фиксированных тиков проходит за единицу реального времени) и не меняют состояние симуляции.

## Ближайший roadmap

Дальнейшая работа идёт по одному combat-спайку за раз:

1. Процедурная читаемая анимация движения на примитивных моделях.
2. Скелетная анимация и импортированные модели.
3. Частицы, освещение, тени и post-processing.
4. Динамическая камера без потери читаемости боя.
5. Performance-бюджеты для слабого десктопа и мобильных.

Правило проекта: playable slice важнее идеальной архитектуры, но simulation остаётся независимой от renderer-а.
