## 3. Фаза 0 — проверка премиссы. Делается ПЕРВОЙ и может отменить всё остальное

Весь срез стоит на одном выводе: «ретиарий дерётся слишком близко к мурмиллону»
— не дефект, потому что гопломах против того же мурмиллона проводит **81.1%**
боя внутри 1.70 против **54.3%** у ретиария и при этом **выигрывает** 55.0%.
Отсюда решение целиться в механики.

Ни один прибор не отвечает, читается ли это так на экране. Поэтому:

```bash
npm run review:clips
```

Посмотреть **`brutus vs drusus`** (мурмиллон против ретиария) и пару, где
мурмиллон против гопломаха. Вопрос ровно один:

> выглядит ли ретиарий прижатым сильнее, чем гопломах, против того же
> противника?

- **Если нет** (гопломах прижат так же или сильнее) — премисса держится,
  идти в фазу 1.
- **Если да** — прибор меряет не то, что видит зритель, и спеку надо
  переосмыслить до реализации. **Это находка, а не провал.** Записать в журнал
  с доказательством и остановиться (раздел 7, пункт 3).

Записать вывод в журнал в любом случае, вместе с тем, что именно было видно.
Клипы — это `docs/reviews/clips/**`, они не в списке запрещённых путей.

## 4. Фаза 1 — PR-2, шов диагностики отходов

**Утверждение PR:** *добавляет шов, не меняет ничего из того, что меряет.*

Образец — `src/simulation/contactDiagnostics.ts`, который предыдущий срез добавил
ровно по этой причине. Читать его первым.

### Что построить

`src/simulation/disengageDiagnostics.ts`, write-only с точки зрения ядра:
никогда не читается внутри тика, не лежит в `EncounterState` и не в журнале
событий, так что ни один хеш трейса по нему не сворачивается.

Одна запись на **завершённый эпизод** форсированного отхода:

- разделение в момент штамповки, прочитанное **в фазе 2, до движения этого
  тика**;
- разделение в момент снятия, прочитанное **в фазе 2, до того как обычное
  решение и движение отработают в том же advance**;
- прошедшие тики;
- **причина выхода из замкнутого перечня** — `range`, `cap`, `progress`,
  `censored` — возвращаемая самим предикатом, никогда не выводимая из
  длительности;
- эпизоды, ещё открытые на конце боя, помечаются `censored`, а не выбрасываются.

`hasFastForcedDisengageEnded` (`combatDecision.ts:1013`) расширяет возврат с
`boolean` до перечня, сохраняя текущую истинностность **точно**. Это
единственное изменение сигнатуры в PR.

### Чего в PR-2 быть НЕ должно

- **Никакого нового поля в `FighterCombatState`.** Поле стартового разделения,
  которое нужно предикату для pursuit-relative логики, идёт в PR-4.
  `src/testSupport/stateHash.test.ts:57-80` сворачивает хеш **всего**
  `BattleState` каждый тик по девяти парам, так что заполненное новое поле
  двигает девять замороженных дайджестов по построению. Коллектор читает оба
  конца в фазе 2, ничего не сохраняя в состоянии — этого достаточно.
- Никакого изменения **логики** выхода и констант.
- Никакого контента, никакой презентации, никаких гейтов
  (`scripts/measure-reach.ts` закрыт).

### Порядок внутри PR

**Сначала коммит с новой границей**, потом работа. `check-allowlist.sh`
пересобрать под утверждение PR-2 и проверить обе стороны: что запрещённый путь

## 5. Правила, которые здесь регулярно кусают

**Ошибается прибор, а не логика, и ошибается в приятную сторону.** За
предыдущий срез так было пять раз. За этот — шесть, и пять из них в пользу
утверждения, которое я делал:

| что | как выяснилось |
|---|---|
| дифф бейзлайнов сравнивался не с тем предком | проверка родословной коммитов |
| промахи выпада «специфичны для мурмиллона» (50 сидов) | 200 сидов: зеркало такое же |
| граница ошибки окна отхода — четыре редакции подряд | фазы 9–10 бьют пушем 0.70 |
| зеркало «в 2 раза активнее» | в зеркале **два** ретиария |
| частота выпада закрыта долей вместо частоты | ревью |
| «стартов строго больше выживших» как инвариант | упало на первом же сиде |

Отсюда правила:

1. **Порядок недоверия:** сначала не верь прибору, потом гейту, потом числам. И
   раньше всего — своему чтению кода: два блокера третьего круга нашлись там,
   где я не открыл файл.
2. **У находки ревью проверяй НАПРАВЛЕНИЕ, а не только существование.**
3. **Черновые прогоны — 50 сидов, но цитировать можно только 200.** Дважды
   50-сидовое число ушло в документ как результат.
4. **Красный гейт прячет гейты за собой.** `npm run check` останавливается на
   первом падении.
5. **Нормализация — часть числа.** Прежде чем сравнивать матчапы, спроси,
   сколько в каждом бойцов нужного типа.

## 6. Как здесь запускаются вещи

`npx` сломан, `node_modules/.bin` нет — всё через `node` напрямую:

```bash
node node_modules/vitest/vitest.mjs run                    # весь набор, ~10 мин
node node_modules/vitest/vitest.mjs run <путь>             # один файл, секунды
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vite-node/vite-node.mjs scripts/measure-reach.ts -- --seeds 200 --gate
node node_modules/vite-node/vite-node.mjs scripts/measure-distance.ts -- --seeds 200
npm run check:allowlist                                    # чистый bash, работает
```

- `dispositionBalance` и `balance` занимают почти весь прогон. Полный набор — в
  конце фазы, по ходу только затронутые файлы.
- Всё дольше 10 минут — через `run_in_background`.
- **Не запускать долгое измерение параллельно с полным набором:**
  `encounter.test.ts` даёт информационную пробу без явного таймаута, ~900 мс
  против дефолтных 5000, и на нагруженной машине она падает. Это записано как
  долг 5 в спеке.
- **Ревью — только `codex`.** `opencode`/deepseek не запускать: шесть попыток,
  один пригодный отчёт, 9–19 минут на попытку.
